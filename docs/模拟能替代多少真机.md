# 「真机跑」能不能用模拟解决？

## 零、先给结论

**能替代一大半，但不能全部替代。** 准确切一刀：

- **「验证程序文本和你的后处理器」这一半 → 可以 100% 在电脑上模拟掉。**
- **「验证这台机床此刻的物理状态」这一半 → 永远模拟不掉。**
- 中间有一档「虚拟机床」可以买，但对我们这个场景不值得。

而且有一个反直觉的点先摆在最前面：**NX 自带的仿真，看不到后处理器。**
你以为仿真跑过了就安全了，其实它根本没检查你最可能出错的那一层。下面会展开。

---

## 一、先修正「后处理 = 编译」

这个类比**对了一半**，但漏掉的那一半恰恰是最关键的一半。

| | 编译（你熟悉的） | 后处理 |
|---|---|---|
| 工具本身 | 编译器是别人写好的，你**只用** | 后处理器就摆在你面前，**等人去改** |
| 你的角色 | 只写输入代码 | 写输入**而且**写后端 |
| 谁的 bug | GCC 团队的 | **你/弟弟/我们自己的** |
| 封闭还是开放 | 封闭黑盒 | **开放式模板**（`.tcl` `.def` 纯文本，可读可改） |
| 改代码后工具变吗 | 不变 | 不变 ✅ 这一点一样 |
| 一次编译到处跑吗 | 同架构可以 | **一台机床一份**，连同型号不同序列号都可能分开 |
| 语法/方言 | 相对统一 | 每台控制器一套方言 |

**一句话差别：**
编译器早被几百万人测过了，没人担心"编译器本身对不对"。
而后处理器是**你刚写的那几行**——你要验证的对象，就是你自己。

所以真正的验证目标是：

> 不是「编译器对不对」，而是「**我刚改的那几行模板对不对**」。

**这个区别直接决定了验证策略**：既然被验证的对象是**纯文本转换**，
那么绝大部分验证都可以用**文本比对 + 静态规则**完成，根本不用碰机床。

---

## 二、把「真机跑」拆成五层

"真机跑"是一个笼统的词。拆开看，它其实在同时验证五件不同的事：

| 层 | 在验证什么 | 用什么验 | 电脑上能做吗 | 成本 |
|---|---|---|---|---|
| ① 语法与安全规则 | 少小数点、缺 M30、S/F 越界、行程超限、刀补没取消 | **自建 `nc_lint`** | ✅ **已实现** | 0 |
| ② 后处理器改动的影响面 | 这次改 `.tcl`，输出到底变了哪里 | **自建 `nc_diff`** | ✅ **已实现** | 0 |
| ③ 刀路几何 | 该切的切没切掉、有没有撞夹具、进退刀方向对不对 | NX CAM 内置仿真 | ✅ 能 | 0（学生版也有） |
| ④ G 代码在**这台控制器**下的行为 | 控制器认不认、G54~G59 偏置对不对、宏程序、换刀时序 | VERICUT / NCSIMUL / CNC Simulator Pro；最高档是 **VNCK 虚拟数控内核** | ⚠️ 能，但要先建整台机床模型 + 控制器参数表 | 很贵 |
| ⑤ 机床物理现实 | 反向间隙、伺服跟随误差、热变形、装夹变形、刀具实际跳动、毛坯余量不均 | **只能真机** | ❌ 不行 | — |

### 三个反直觉的点（都是查权威实践查到的）

**1）NX 内置仿真看不到后处理器。**
它仿真的是「刀路」——软件内部的数据结构，不是后处理之后的 G 代码。
**后处理器写错了，内置仿真照样显示一切正常。**

> 原文：Most CAM simulators display the internal Cutter Location (CL) data — not the
> post-processed G-code... the built-in simulator does not always re-examine that transform.

→ 所以第 ② 层必须自己补。**这正是 `nc_diff` 存在的理由。**

**2）仿真器不运行控制器，它只是模仿控制器的解析器。**

> 原文：Even an external G-code simulator **models** the controller's parser;
> **it does not run it**. The actual machine controller ... is the only environment
> that executes the exact block-by-block interpreter that will cut the part.

→ 第 ④ 层永远有一道缝：仿真器说没事，控制器可能报警；仿真器报警，控制器可能没事。

**3）机床个体差异不在任何模型的输入里。**
同一型号不同序列号的机床，调机参数（反向间隙、丝杠螺距补偿）都不一样，
所以连后处理器都是按**序列号**分开维护的。

> 原文：Shops running multiple 5-axis machines with the same nominal model number
> often maintain separate posts per serial number because commissioning parameters
> differ between individual machines.

→ 这条直接说明第 ⑤ 层为什么模拟不掉：**你要验证的东西，压根没进模型。**

## 三、还有一个「真·虚拟机床」档位（知道存在即可）

**VNCK（Virtual NC Kernel）** 是西门子那一套虚拟数控内核。
它把**控制器的真实逻辑和参数**搬进电脑——同样的加减速特性、同样的换刀时序、
同样的语法容错行为。这是唯一接近"真机跑"的模拟方式。

但代价很大：要建整机模型、要对上控制器选项表、要对上参数。
业内一般只用在**航空 / 医疗 / 国防**的高价值件上。

对我们的场景（模具厂），**不值得**。知道它存在就够了——
万一哪天要加工一个几十万的模具，那时候再谈。

## 四、落到我们这件事：一次具体案例

用刚做的两个样例，演示「改一次后处理器，电脑上到底能查出什么」。

背景：弟弟改了后处理器的 `.tcl`，想加个程序头注释。改完出了新程序。
**他担心的是：我真的只加了注释吗？**

跑一句命令：

```
python verify/nc_diff.py samples/POST_GOLDEN.NC samples/POST_AFTER_TCL_EDIT.NC
```

输出（节选）：

```
NC 回归比对报告
  golden : samples/POST_GOLDEN.NC（18 行有效指令）
  new    : samples/POST_AFTER_TCL_EDIT.NC（19 行有效指令）
  相同 17 / 新增 1 / 删除 0 / 修改 1

  结论：有差异
  风险：**高** —— 差异落在 刀长补偿、坐标值、转速或进给、运动指令 上，
        这些直接决定机床怎么走，必须人工逐条确认。

[1] 修改 高危  golden#12 -> new#14
     - G01 X80. Y0. F1500
     + G01 X80. Y0. F1200
     ! 命中：坐标值、转速或进给、运动指令
[2] 新增 高危  new#20
     + G40 G49
     ! 命中：刀长补偿
```

**看出来了吗**：他"以为只加了注释"，实际上**顺手把进给从 1500 改成了 1200**。
这不是注释，这是切削参数。如果不比对，这个改动会直接上机床。

（这个 `isError=true` 已经接进 MCP 了，Agent 自己就会跑这一步并拦住。）

### 谁负责抓哪一类错

| 典型改动 | 谁抓 | 后果 |
|---|---|---|
| 程序头多一行 `(PROGRAMMER: ...)` | `nc_diff` → **低危**，放过 | 无害 |
| `F1500` → `F1200` | `nc_diff` → **高危** | 切削参数变了 |
| 多一句 `G40 G49` | `nc_diff` → **高危** | 刀长补偿被取消 |
| 少写小数点，坐标差 1000 倍 | `nc_lint` + `nc_diff` 都能抓 | 撞机 |
| 控制器不认的语法 | **只能靠控制器**（但 `nc_lint` 规则表可以不断补） | 报警 |
| 实际切削震刀、尺寸超差 | **只能真机** | 废件 |

注意最后两行——**这才是模拟替代不了的部分。**

## 五、所以最终能干到哪一步

### 电脑上（全自动，Agent 自己跑，不需要人）

1. `nc_lint` —— 语法 + 安全规则体检
2. `nc_diff` —— 跟 gold 基准比对，自动分高危/低危
3. NX 内置仿真 + 截图（Agent 看截图，作辅助判断）
4. 有多个后处理器/多种参数时：批量生成 + 批量比对

### 上机（必须人，但次数被压到最低）

5. 控制器空运行（DRN 模式 / 单段 / M01 可选停止）——**控制器是最终权威**
6. 抬刀空切
7. 首件试切 + 首件检验

### 一句话总结

> 模拟能把「上机次数」从**每次改动都上机**，
> 压到**只有首次 + 关键变更才上机**。
>
> 但**上机这一步删不掉**——因为它在验证的东西（这台机床此刻的物理状态），
> 根本不在任何模型的输入里。

对我们来说，这个程度的压缩**已经足够值了**：
弟弟改后处理器的频率可能是每周几次，上机的代价是一次几十分钟 + 撞机风险。
把这部分从"靠经验赌"变成"跑一条命令 + 看差异分类"，是实打实的收益。

## 六、顺手一个可能值钱的发现（⚠️ 未验证）

搜 NX 官方文档时发现：NX 提供了一个 `runugpost.exe`，
**可以在不启动 NX 的情况下跑后处理器**。

- 路径：`%UGII_BASE_DIR%\MACH\auxilliary\runugpost.exe`
  （注意 Siemens 文档里这个目录名拼作 `auxilliary`，双 l，不是笔误）
- 需要环境变量 `UGII_CAM_POST_CONFIG_FILE` 指向一个 `.dat` 配置文件，
  内容格式是每行「机床名, 事件处理.tcl, 格式.def」
- `UGII_CAM_POST_DIR` 指向上面的文件所在目录
- 另外 NX 可以把刀路导出成 **CLSF 文件**（纯文本的标准刀位文件），配合第三方后处理器使用

**为什么这条可能值钱**：
如果它能在学生版上跑通，那"学生版不能后处理"这个限制就被绕开了——
我们就能在开发机上把后处理这一段**真正跑起来**，
而第 ①② 两层的验证都要以"能出 NC 文件"为前提。

### 但是，先自我打假

- 学生版的限制几乎肯定是在**许可证层**生效的，不是在界面上。
  `runugpost.exe` 大概率撞同一堵墙。
- 我搜到的是 **NX 8.0 时代的官方帮助文档**，现在（NX 2506 / Designcenter）行为不一定一样。
- **完全没有真机验证过，不要当成解决方案。**

**它值多少钱**：值一次 5 分钟的实验。
等 NX 装好了，拿现成的 `template_post.dat` 配好环境变量，
用 `runugpost.exe` 试一次，就知道行不行。不行的话，5 分钟损失，可以接受。

## 七、这一步要问弟弟什么

第 ④⑤ 层的验证需要真机信息。可以复制给他：

> 弟，再问你几个：
>
> 1. 你们机床的数控系统是什么牌子型号？（看操作面板上的字，FANUC 0i / 三菱 M70 /
>    西门子 828D / 新代 / 宝元 …… 拍照最省事）
>
> 2. 程序传到机床后，上机前你会不会先用"空运行"跑一遍？
>    面板上有没有叫"空运行 / DRY RUN"的按钮或者参数？
>
> 3. 有没有遇到过"在电脑上看没问题，一到机床上就报警"的情况？
>    报警号是多少？（这个最能说明控制器的脾气）
>
> 4. 首件加工完之后，你怎么确认尺寸对不对？卡尺、千分尺，还是有三坐标？
>
> 5. 你们厂里改过程序的开头结尾吗？是每个人自己改，还是有人统一管着一个模板？

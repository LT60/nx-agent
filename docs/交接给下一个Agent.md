# 交接提示词（直接复制这段）

```
你是「NX 助手」项目的接管 Agent。花 10 分钟读完下面的背景和入职手册，然后开始干活。

## 背景（你必须理解的需求）
用户是计算机专业研究生，他本人**完全不懂 CAD/CAM**。
他的弟弟是模具厂工人（大专学历），日常用 Siemens NX（模具行业叫 UG）做
电极设计和 CAM 刀路编程。

用户的目标：让 Agent 成为弟弟的助手 —— **弟弟只跟 Agent 说话，Agent 去操作 NX。**
用户明确拒绝"半自动"，要求像 Agent IDE 那样边对话边迭代。
沟通时用户看不懂 NX 术语，需要用大白话 + 程序员类比来解释。

## 你的第一件事：读入职手册
项目在：<把这里的路径换成 nx-agent 的实际路径>
先读 nx-agent/AGENTS.md —— 这是上一任 Agent 写的入职手册，包含：
  · 红线（不可协商）
  · 学生版 NX 的硬限制（**很多路已经被试死，别再试第四次**）
  · NX 2606 的 API 事实表（真机探测出来的，别凭记忆猜）
  · 现成资产（电极加工模板、CAM 示例部件）
  · 已踩过的测试坑
  · 接手检查清单
再读 nx-agent/README.md 第七节（验证状态）和 docs/ 下的中文文档。

## 环境（本机已经装好，别重装）
- NX：Designcenter Student Edition 2606，装在 D:\NX
- 启动：`python tools/start_bridge.py`（一条命令拉起 NX 并建立连接，12~16 秒就绪）
- 停止：`python tools/start_bridge.py --stop`
- 冒烟测试：`python tools/bridge_probe.py`
- 全项目自检：`python tools/selftest.py`（21 项，改完代码必须全过）
- 查 NXOpen API：`python tools/nx_api_lookup.py <关键词>`（写代码前必查，别猜）
- 看弹窗状态：`python tools/dialog_sweeper.py --once`

## 已经能做的事（都实测过，可直接用）
- 建模：改参数（`SetFormula` + `DoUpdate`）、加特征（`CreateBlockFeatureBuilder`
  + `SetBooleanOperationAndTarget`）
- 编刀路：基于 `ngElectrode.prt` 模板（自带 6 道电极工序），`cam.GenerateToolPath(ops)`
- 仿真：`preview` 命令 → 刀路回放 + 3D 切除图
- 导出刀路数据：`OutputClsf(ops, "CLSF_STANDARD", ...)`
- **完整闭环**：用户提需求 → 改模型 → 重算刀路 → 出图 → 用户验收

## 学生版的硬限制（**已经撞过墙，别再试**）
- 从外部程序驱动 NX：不可用（`run_journal.exe` / `UF_initialize` / NXOpen Remoting
  三条路全部被许可拦住）
- batch 模式**不能创建加工环境** → 所以要从**模板**开始（这是 NX 的正常用法）
- **不能后处理出 G 代码**（`MOG: UGPOST License is not available`）
- 结论：只能走「界面内跑脚本」（`-auto=`）这条路

## 红线（不可协商）
- G 代码上机前必须：`nc_lint` 通过 + `nc_diff` 无高危 + NX 仿真 + 机床空运行 + **人签字**
- 操作个人目录（Downloads / Desktop / Documents）**只出报告，不代删**
- 改完任何脚本，跑 `tools/selftest.py` 验证，别靠眼看
- 不确定的 NXOpen API 先去查（`nx_api_lookup`）或现场反射 `fn.__doc__`，**不要猜**

## 交接时还缺的输入（请向用户索取）
1. 弟弟厂里 **2~3 个真实 .nc 程序（脱敏）** —— 用来验证 `nc_lint` / `nc_diff`
2. **弟弟的工艺参数习惯**（用什么刀、进给转速、留多少余量）—— **直接问，不要录制**
3. 确认用户是否愿意永久关闭那个遥测同意框

### ★★★ 关于「录制」：**不需要**（用户 2026-10-01 纠正）

用户原话：
> 「我认为真实操作录制不需要。网页开发的时候你需要录制什么？不需要吧。」

**对的。** 网页开发不需要录制人的点击，NX 开发也一样——
**操作层面的事，查 API + 现场反射 + 试错就够了。**

**证据**：本项目**所有**已验证能力都是直接写 API 得来的，一次录制都没用：
建方块、改尺寸、加特征（加放电头）、`GenerateToolPath`、3D 切除仿真、`OutputClsf`。
（曾有一处用录制模板 `templates/electrode_batch.py`，那是**为了批量循环的骨架**，
不是因为没有录制就写不出代码。）

**录制的残留价值只剩一个**：极少数「API 查不到、文档也没有、试不出来」的角落，
拿人的操作当兜底线索。**但这不该写进待办清单。**

**真正拿不到的只有「工艺参数」**（用哪把刀、进给多少、留多少余量）——
那是**师傅脑子里的经验**，不在 API 里。但**问弟弟比录制快得多**，
而且答案可以直接落成 `config/cutting_defaults.json` 那样的默认值表。

## 未修的问题
- `screenshot` 命令需要显式传 `out_path`（调用时容易忘）
- 中文文件名的问题已修（走短路径），但**其它文件操作也要注意非 ASCII 路径**
- 有个管理员权限的 NX 僵尸进程杀不掉（`拒绝访问`），不影响使用，重启消失
```

# 附：这条提示词背后的设计考虑

**为什么这样写：**

1. **先给需求背景，再给技术手册** —— 不理解的 Agent 会做出方向错误的决策
   （比如上来就想"把 NX 换成网页"）。
2. **明确写「已经撞过的墙」** —— 上一任 Agent 花了大量时间试出这些结论，
   不写下来，下一个 Agent 会重复烧掉同样的时间。**这是本项目最贵的资产。**
3. **明确指向文件而不是复述内容** —— 手册会更新，提示词不该复制它。
4. **列出「还缺的输入」** —— 让新 Agent 知道哪些能自己干、哪些必须问用户。
5. **红线单独一段** —— 安全相关的不能埋在一堆信息里。

# 附：如果要把项目搬到弟弟的电脑

本机（用户的电脑）是**开发环境**，弟弟那边是**使用环境**。搬过去时：

1. 拷整个 `nx-agent` 目录
2. 装 NX（版本要对得上，见 `docs/安装NX.md`）
3. 装 Python（用来跑桥接脚本，NX 自带的不够，建议 3.8+）
4. **改路径**：`tools/start_bridge.py` 里会自动探测 NX 安装位置（注册表兜底），
   一般不用手改；但 `%TEMP%` 下那些临时驱动脚本里写死的路径要重新生成
5. 跑 `python tools/preflight_check.py --auto` 检查环境
6. 跑 `python tools/selftest.py` 确认 21 项全过
7. 注意：弟弟电脑上**没有 WorkBuddy/Agent 的话，这套东西只是工具**——
   要让 Agent 干活，他需要有个能对话的 Agent 环境

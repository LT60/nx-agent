**先找到安装器**：打开「文件资源管理器」→ 左侧点「下载」，
或者在上方地址栏直接粘贴 `C:\Users\lt\Downloads` 回车。

- [ ] **双击 `SSCInst.exe`**（44 MB 那个）
      —— 或者从 SSC 官网链接下最新版：`https://www.siemens.com/en-us/support/siemens-software-center/`
- [ ] 它会安装一个叫 **Siemens Software Center** 的小程序（不是你想象中那个 19GB 的 NX）
- [ ] 装完打开 SSC，**用第 1 步注册的同一个邮箱**登录

⚠️ 两个容易卡住的点：

1. **邮箱必须和第 1 步注册 Trial 时用的完全一样。** 不一样的话登录进去是空的。

### 第 3 步 · 下载 NX

- [ ] 在 SSC 里找到 **Designcenter Student Edition**

- [ ] 点 **Install**（或点右上角三个点看安装选项）
- [ ] 等安装完成（30～90 分钟，中途别关）

> 网上很多教程会说"展开 `Programming Tools`，把 `Programming Interfaces` 勾上"。
> 那是**商业版**安装程序的步骤。**学生版的安装包没有这个选项。**
>

> `FEAT_CORE` / `FEAT_NXPLATFORM` / `FEAT_CORE_SSC` / `FEAT_SAAS`，
> 没有任何可选的功能树。`run_journal.exe` 属于核心组件，**装了就有**。
> 所以这一步你不用操心，也**不要**去找那个勾选框（找不到的）。

#### 想把 NX 装到 D 盘（或别的非系统盘）怎么办

**先说清一件事：NX 装完之后不能"剪切粘贴"迁移。**
注册表、`UGII_BASE_DIR` 环境变量、还有一堆模板文件里全是写死的绝对路径，
挪个文件夹必然崩。想换盘，**只有一个办法：卸载 → 重装**。

**好消息：安装包本身支持自选路径。** 我在它的 MSI 属性表里确认了：

```
WIXUI_INSTALLDIR       = INSTALLDIR                 ← 安装界面里有「选路径」的对话框
SecureCustomProperties = INSTALLDIR;...             ← INSTALLDIR 可以从命令行覆盖
```

之前之所以装到了 C 盘，是因为 **SSC 替你做了决定** ——
它在日志里自动传了 `INSTALLDIR="C:\Program Files\Siemens\DcStudentEdition2606\\"`，压根没给你选的机会。

**安装包在这里**（卸载时**不要**删掉这个目录）：

```
C:\Users\lt\Downloads\
  SiemensDesigncenterStudentEdition-2606951750887046343963_files\      ← 解压出来的安装源，约 9.8 GB
    SiemensDesigncenterStudentEdition-2606.3002_wntx64\
      SiemensDesigncenterStudentEdition.msi                            ← 就是它，双击即可
      （旁边还有 100 多个 .cab 文件，是数据包，不能挪走或删除）
```

**装法一：双击 MSI（有界面）**

直接双击上面那个 `.msi`，一路往下走，中间会有个按钮让你改安装路径，
改成 `D:\Siemens\DcStudentEdition2606` 就行。
（需要管理员权限，会弹 UAC。）

**装法二：命令行（最精确，推荐）**

以**管理员身份**打开命令提示符，粘这一行：

```bat
msiexec /i "C:\Users\lt\Downloads\SiemensDesigncenterStudentEdition-2606951750887046343963_files\SiemensDesigncenterStudentEdition-2606.3002_wntx64\SiemensDesigncenterStudentEdition.msi" INSTALLDIR="D:\Siemens\DcStudentEdition2606" UGII_LANG=simpl_chinese ADDLOCAL=ALL REBOOT=R /l*v "D:\nx_install.log"
```

| 参数 | 作用 |
|---|---|
| `INSTALLDIR="D:\Siemens\DcStudentEdition2606"` | 装到哪（**这是你要改的那个**） |
| `UGII_LANG=simpl_chinese` | 界面语言，中文。不想要中文就整段删掉（默认英文） |
| `ADDLOCAL=ALL` | 全部组件都装（跟 SSC 用的参数一致，不会漏东西） |
| `REBOOT=R` | 装完不自动重启 |
| `/l*v "D:\nx_install.log"` | 把安装日志写到 D 盘 —— **出问题全靠它**，建议保留 |

> 这三个参数（`INSTALLDIR` / `UGII_LANG` / `SPLMLICENSESERVER`）都是 MSI 明确声明
> 「允许从命令行传入」的（它们在 `SecureCustomProperties` 白名单里），传了**一定生效**。

**卸载旧的那份**（如果还没卸干净）：

```bat
msiexec /x {2DAFE35D-E180-4002-A6F5-9A2991AF66FD}
```

或者：设置 → 应用 → 找到 **Siemens Designcenter Student Edition 2606** → 卸载。

### 备选方案：目录联接（万一 SSC 认不出 D 盘那份）

**背景问题**：上面是绕过 SSC 手工装的，SSC 自己的记录文件
（`C:\ProgramData\Siemens\SoftwareCenter\data\machineData.json`）里**不会**出现这次安装。
SSC 的「激活」功能如果依赖这份记录，就可能找不到产品。
（也有可能是 SSC 会自己扫注册表发现它 —— 注册表里 MSI 会正常写
`HKLM\SOFTWARE\Siemens\NXStudent 2606\INSTALLDIR = D:\...`。**先试，试了才知道。**）

**如果 SSC 确实认不出**，就走下面这条路 —— 它能让「官方路径」和「实际存储」分离：

1. 把 NX 装到**官方默认路径**（`C:\Program Files\Siemens\DcStudentEdition2606`），
   让 SSC 全流程正常走完，激活也在这时候做
2. 确认 NX 能正常启动、激活有效
3. 关闭所有 NX 进程，把整个 `C:\Program Files\Siemens\DcStudentEdition2606`
   **剪切**到 `D:\Siemens\DcStudentEdition2606`
4. 在**原位置**建一个目录联接，把它指回 D 盘：

```bat
mklink /J "C:\Program Files\Siemens\DcStudentEdition2606" "D:\Siemens\DcStudentEdition2606"
```

结果：**所有程序看到的仍是 C 盘那个官方路径，实际数据全在 D 盘**，C 盘只剩一个联接。

> **这个方案我实测验证过了**（在真机上跑过一轮），四条结论：
> | 验证项 | 结果 |
> |---|---|
> | 通过联接读文件 | ✅ 完全透明，读到的内容和真实目录一致 |
> | 通过联接写文件 | ✅ 写穿透到真实目录 |
> | **磁盘空间查询** | ✅ **跟随真实所在盘**（查联接路径返回的是 D 盘的 1278 GB，不是 C 盘的 40 GB）—— 所以安装程序不会误判空间不足 |
> | 删掉联接本身 | ✅ 只删联接，**真实数据安然无恙** |
>
> `mklink /J` 建的是「目录联接」（junction），**不需要管理员权限**，也不像符号链接那样受限制。

**⚠️ 手工装的三个副作用（提前知道）**

| 副作用 | 说明 |
|---|---|
| SSC 里可能显示「未安装」 | 因为 SSC 记的是它自己装的那份。**不影响 NX 运行**，但以后更新/卸载要在「设置 → 应用」里手工做 |
| 激活仍要走 SSC | 授权是另一个系统（SALT 云端），跟装在哪没关系。装完照常去 SSC 登录取授权 |
| 官方不背书非默认路径 | 非默认路径属于「能跑但不承诺」，遇到怪问题时先怀疑这个 |

**⚠️ 千万别删的东西**

- `..._files\` 那个解压目录（9.8 GB）—— 重装要用的安装源
- 只有 `SiemensDesigncenterStudentEdition-*.zip` 那个 9.7 GB 的压缩包是冗余的
  （解压都解完了），**装完确认没问题再删**

**装完自检**（这是确认有没有真的装好的唯一办法）：

```bash
python tools/preflight_check.py --auto
```

它应该自动找到 D 盘那个目录，并且 `run_journal.exe` / `NXOpen.pyd` 都是 `[ OK ]`。

> **一句话权衡**：如果只是想腾 C 盘空间，**删掉那 19.5 GB 的下载残留就够了**，
> 不用折腾重装。只有当你要长期在 D 盘用 NX 时才值得重装。

### 第 5 步 · 装完自检

- [ ] `python tools/preflight_check.py --auto`
- [ ] 看 `ugraf.exe` / `run_journal.exe` / `NXOpen.pyd` 几条是不是 `[ OK ]`
- [ ] 看「学生版授权」那一节有没有告警（有的话见本文第七节）
- [ ] `python tools/start_bridge.py` —— **一条命令把 NX 和桥接一起拉起来**，
      等它打印「桥接就绪」即可（首次约 13~40 秒）

> 这是**最终目标**，第 5 步能走到这里，后面就只剩「我给 Agent 加能力」这件事了。

## 四、SSC 里看不到「Designcenter Student Edition」怎么办

**先理解 SSC 的工作原理**：它是个**空壳下载器**，只会显示「你账号名下有权使用的东西」。

> 列表是空的 = **你的账号上没有这项授权（entitlement）**，
> 不是软件坏了，也不是网络问题。

按这个顺序排查，前两条命中率最高：

### 1. 确认「Trial Details」填了、而且点了 Launch ← 最常见

**光注册账号、光登录，都不算报名成功。**

回注册页再看一眼：如果页面还停在 "Trial Details" 表单、或者那个 **Launch** 按钮你没点，
说明**试用根本没有开始**，SSC 里当然什么都没有。

```
https://trials.sw.siemens.com/zh-CN/trials/nx-cad-cam-student-edition
```

打开后要看的是：页面上还显示不显示 "Launch" 这类按钮。显示 = 还没启动，点它。

### 2. 确认邮箱完全一致

SSC 登录用的邮箱，必须和**注册 Trial 时用的那个**一模一样（大小写无所谓，但必须是同一个地址）。
不一致就登出，换成注册时那个邮箱登入。

### 3. 确认选到了「我的产品」选项卡

SSC 窗口里要选到 **"My products" / 「我的产品」** 那个选项卡。
官方入门文档原话：「在 Siemens Software Center 窗口中，确保**我的产品**选项卡已选中。」

### 4. 完全退出再重开（授权下发有延迟）

新开的试用，授权下发有时要几分钟。
**完全退出** SSC（右下角托盘图标也要退出），等几分钟，再打开。或者登出再登入。

### 5. 还是空的 → 找官方提单，让他们给你挂上授权

这是官方文档里给的正式做法，不是野路子。

官方 SSC 入门文档（KB000190593）原话：

> To see products in SSC, your Enterprise Cloud Account (ECA) administrator must assign
> them to your user in the Siemens Xcelerator Admin Console. **If products are assigned
> but still not visible, submit a support case via Support Center.**

官方学生版博客原话：

> If you experience any errors or issues with accessing the software, please submit a
> ticket with as many details as possible (including screenshots if you have any) to
> Siemens Digital Industries Software Support Center. **They can ensure your account has
> the correct entitlements.**

提单位置：`https://support.sw.siemens.com/`

提单时把这些写清楚（省得来回问）：

- 我用的是**免费 Designcenter / NX Student Edition 试用**，不是商用授权
- 注册用的邮箱：______
- 注册时间：______
- 症状：SSC 已登录（同一个邮箱），但产品列表为空
- 附截图

> 因为学生版是**免费试用**，没有公司站点（Site-ID），
> 所以走的是「support case 让他们给你账号挂 entitlement」这条路，
> 不是找 IT 管理员。**免费这一点要主动说明**，否则可能被当成商用问题转来转去。

### ⚠️ 顺便排除一个坑：别去错门户

**不要去 `mall.industry.siemens.com` 或「工业商城」那类产品目录里找。**

那是**商用授权**的下载门户（TIA Portal、WinCC、SINUMERIK 这些），

## 五、五个坑（记住就行，不用背）

1. **学生版不能后处理。** 官方原话："CAM data is not available for post-processing,
   and the displayed output of tool path information has limited precision."
   → 你测不到"出 NC"那一步。这没关系，但 `nc_lint` / `nc_diff` 需要真实 `.nc`

3. **学生版存的 .prt，商业版打不开。** 别拿它给用户做生产文件，会污染他们的数据。

5. **没有自动更新，也没有月度补丁。** 每个大版本系列只有最初那个版本，
   要更新就在 SSC 里手动装下一版。

## 六、下载一个字节都下不来怎么办

### 先跑诊断脚本（1 分钟）

```bash
python tools/net_probe.py
```

它把「能不能解析域名 → 能不能连上 443 端口 → TLS 加密握手能不能成」三层分开量。
**看哪一层红的，就知道病在哪**：

| 红的层 | 含义 | 对策 |
|---|---|---|
| DNS | 域名被污染，解析不出 IP | 换 DNS（8.8.8.8 / 1.1.1.1），或走代理 |
| TCP 443 | 端口被丢包，连都连不上 | 走代理 |
| **TLS 握手** | **TCP 通了，但发出 ClientHello 后对方永远不回** | **走代理，且必须让 SSC 的流量真的过代理** |

**TLS 层挂死是最常见的情况**，特征很好认：TCP 两百多毫秒连上，
然后握手一直卡着，直到超时。这在术语上叫 **SNI 阻断** ——
中间设备看见你要访问哪个网站（TLS 握手时域名是明文的），就把后续的包丢掉。
结果是"能连上但拿不到任何数据"，也就是你看到的现象。

### 怎么判断"是不是文件太大"

不用猜，看两个数：

1. **SSC 日志里，小文件（几十 MB 的运行时）也一起失败了吗？**
   日志在 `C:\ProgramData\Siemens\SoftwareCenter\logs\ssc_history_*.txt`。
   搜 `下载已中止`。如果 `VC_redist.x64.exe`（25 MB）这种也在里面 —— 那就跟大小无关。
2. **下载目录里那些分片文件是多大？**
   比如 `SiemensDesigncenterStudentEdition-*.zip0` ~ `.zip5`。
   如果是 **0 字节**，说明**一个字节都没传过来**，不是"下到一半断"。
   如果是有几十 MB 的残缺文件，那才是真的网络不稳、断点续传能救。

### "为什么开梯子也一样"—— 最可能的原因

**SSC 这个客户端很可能根本不读 Windows 的系统代理设置。**
系统代理是给浏览器一类程序准备的；SSC 是独立客户端，它更可能直接用底层的网络连接。
所以你在 clash 里点"系统代理"开关，SSC 那边完全没感觉到，还是直连，
还是被 SNI 阻断 —— 表现就是"开不开梯子一个样"。

**还有一种可能**：clash 用的是规则模式，而 `siemens.com` 不在任何规则集里，
默认落到 `DIRECT`（直连）。那即使系统代理生效，西门子的流量还是直连出去。

### 按成功率排序的解法

| # | 做法 | 为什么有用 |
|---|---|---|
| **1** | **让 clash 开 TUN 模式（虚拟网卡模式），并切「全局 / Global」模式**，然后重试下载 | TUN 是在网卡层接管**所有**进程的流量，SSC 认不认系统代理都无所谓；全局模式避免规则把西门子丢直连。**这一步最可能一次解决。** |
| 2 | 如果不想用 TUN：clash 切全局模式 + 确认 SSC 走代理。**验证方法**：点下载的同时，去 clash 的「连接」页，按进程名找有没有 SSC 的连接 | 能亲眼看到 SSC 到底连了哪个域名、走的哪个节点，比猜强 |
| 3 | 用 **Proxifier** 之类的工具，强制把 `SiemensSoftwareCenter.exe` 的流量丢给代理 | 进程级强制，绕开"应用不认系统代理"的问题 |
| 4 | 换网络环境：**手机热点**（同运营商效果一般）、**学校 / 公司网络**（出口可能不同） | 换出口。要换就换一个真正不同的出口 |
| 5 | **直接在用户的机器上下载和安装** | NX 最终本来就是要装在他那台机器上跑生产的。你的机器只是开发环境 |

### 兜底：这一步不阻塞主线

装不上 NX **不影响已经做完的部分**：

- `tools/selftest.py` 的 **14 项自检已经全通过** —— 校验层（`nc_lint` / `nc_diff`）
  是**离线**的，不需要 NX 在线，也不需要许可证。
- 而这两个校验器要真正可信，靠的是**用户厂里真实的 `.nc` 程序**当基准，
  不是靠你本地装的 NX。
- 所以**现在就可以找用户要两三个脱敏的真实程序**（把公司名、客户名、零件号改掉即可），
  不用等下载成功。

> **术语对照**
> - **TLS 握手** ≈ 打电话时先"喂，是我，你是哪位"互相确认身份、约定用什么暗号。
> - **SNI** ≈ 这个"你是哪位"的电话里，你**必须先报出你要找谁的门牌号**，而且不加密。
>   中间人看到门牌号不对就把线掐了。
> - **TUN 模式** ≈ 给电脑外挂一张虚拟网卡，所有程序出门都得先经过它，没人能绕过。
> - **断点续传** ≈ 下载像搬砖，搬了一半可以先歇着，下次接着搬，不用从头。

## 七、装完了但 NX 起不来：许可证激活失败

### 症状长什么样

- 安装过程一切正常，文件都到位了（`run_journal.exe`、`NXOpen.pyd` 都在）
- 但一启动 NX 就报许可证错误。用命令行跑 `run_journal.exe` 会看到：

```
fatal error
run_journal: Failed to initialize user function for the run_journal application. Error Code = 948822.
License Error, SPLM_LICENSE_SERVER needs to point to a license server.
```

**这里的坑是：这句话会把你带偏。** 它让你以为要去配 `SPLM_LICENSE_SERVER` 环境变量 ——
但学生版根本不走这条路（见下一节），所以你会怎么配都不对。

### 真正的原因：激活那一步失败了

证据在 SSC 日志里，搜 `激活` 和 `SALT`：

```
许可信息 [CSA0101] 激活
    Trying to activate: Designcenter Student Edition With Activation code: 4dd050e1-...

许可信息 [CSA0047] 激活失败。
    SALT_status_not_activated: 订阅并似乎未激活。

许可信息 [CSA0003] 激活/取消激活失败。
    SALT 状态：SALT_status_bad_credentials: 凭证已被订阅服务器拒绝。

激活错误 [CSA0079] 激活 Designcenter Student Edition 失败。
    凭证已被订阅服务器拒绝。
```

**为什么会这样** —— 看同时段的另外两条：

```
19:54:54  身份验证错误 [CSA0002] 刷新令牌失败。
19:56:47  身份验证已过期 [CSA0169] 应重新启动 Siemens Software Center。
```

**链条是这样的**：

1. 下载慢，整个流程拖了一个多小时（19:02 开始，19:56 才结束）
2. 期间 SSC 的**登录令牌过期**了
3. 安装本身照样完成了（装文件不需要令牌）
4. 但最后一步**激活许可证要用令牌**，令牌已过期 → 被服务器拒绝
5. 结果：**文件全都在，就是没有有效许可证**

> **术语对照**
> - **激活（Activation）** ≈ 拿你的账号去厂家那里领一张"使用资格证"，领回来存在本机。
> - **令牌（Token）** ≈ 那张"身份证明"，有时效。登录一次给你一张，过期要重新登录再拿。
> - **SALT** ≈ 西门子的授权技术名字（Siemens Advanced Licensing Technology），
>   学生版用它做云端激活；商业版用的是另一套（FlexLM + 许可证服务器），两套互不相干。

### 怎么解决

**一句话：打开 SSC，重新登录，让它把激活跑完。**

1. 打开 **Siemens Software Center**（开始菜单里搜）
2. **登录**（用注册 Trial 时那个邮箱）
3. 找到 **Designcenter Student Edition**，看它是不是有"激活 / Activate"之类的入口
4. 如果状态不明确，**直接再点一次 Install** —— 文件已经在本地了，
   这一步主要就是重新走一遍激活，不会重下 10 GB
5. 看 SSC 日志确认这次没有 `激活失败`
6. 再跑一次自检：

```bash
python tools/preflight_check.py --auto
```

看到这条是 `[ OK ]` 才算真的好了：

```
[ OK ] 授权激活状态    日志里没有发现激活失败
```

### 怎么自己查

自检脚本已经内置了这个检查，它会直接告诉你激活是成是败、证据是哪几行：

```bash
python tools/preflight_check.py --auto
```

手动查的话，看这两个地方：

| 看什么 | 在哪 | 正常应该是什么 |
|---|---|---|
| 授权登记 | 注册表 `HKLM\SOFTWARE\Siemens\NXStudent 2606` | 有 `LICENSESERVER = 29000@LocalHost` |
| 激活结果 | `C:\ProgramData\Siemens\SoftwareCenter\logs\ssc_history_*.txt` | 没有 `激活失败` / `SALT_status_bad_credentials` |

### 顺便纠正一个误解：学生版不需要 `SPLM_LICENSE_SERVER`

学生版**不装传统许可证服务器**，安装目录里没有 `lmgrd.exe` / `ugslmd.exe`，
也**不会**写 `SPLM_LICENSE_SERVER` 环境变量。所以：

- 自检报 `SPLM_LICENSE_SERVER 未设置` 在**学生版上是正常的**，不是问题
- 注册表里那个 `LICENSESERVER = 29000@LocalHost` 是 SALT 组件的地址，
  平常没人监听它也是正常的 —— NX 启动时才会拉起来
- 别去手工设 `SPLM_LICENSE_SERVER=29000@LocalHost` 然后以为能修好，
  **根本没激活的话，设了也没用**

### 顺手把桥接跑起来（一条命令，不用点鼠标）

```bat
cd /d D:\nx-agent
python tools\start_bridge.py
```

它会自己找到 `ugraf.exe`、自动补 `-student`、用 `-auto=` 让 NX 启动时

三项（心跳 / ping / info）全 PASS 就说明桥接真活了。**让它开着别关**，
然后在 Agent 那边正常对话即可。

停止：`python tools\start_bridge.py --stop`

> 手工播放的备选路径（不想让脚本代劳启动 NX 时用）：
> NX → `Developer` 选项卡 → `Journal Manager` → `Browse` 选中

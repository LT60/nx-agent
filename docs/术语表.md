# NX 术语表（给不懂 CAD/CAM 的人看）

读法：**词** —— 大白话解释。括号里是给程序员的类比。

---

## 一、软件和文件

- **UG / NX** —— 同一个软件的旧名和新名。西门子收购 UG 之后改名 NX。弟弟嘴里说"UG"，
  官方文档写"NX"，是同一个东西。
- **CAD** —— 计算机辅助设计，就是用电脑把零件画成 3D。对应弟弟说的"建模"。
- **CAM** —— 计算机辅助制造，就是不光画出来，还算出机床该怎么走刀。对应弟弟说的"编程"。
- **CAE** —— 计算机辅助工程，算强度、热、流体。本话题里基本不用管。
- **建模** —— 把零件在电脑里画成 3D 实体。
- **.prt 文件** —— NX 的零件文件，几何、特征、刀路全在里面。
  （类比：一个二进制序列化文件，不是文本，git 管不了它。）
- **工作部件（Work Part）** —— NX 同一时刻"当前打开的那一个"零件文件，所有操作都作用在它身上。
  （类比：当前工作目录 cwd。）
- **特征（Feature）** —— 建模时一步一个的"积木"：拉伸、倒角、打孔。它们按顺序排成特征树，
  改前面的会自动更新后面。（类比：可重放的构建流水线 / Git 提交历史。）

## 二、加工相关（弟弟天天打交道的）

- **刀路（Toolpath）** —— 刀具在空间里走的路径：一串点，加上每段走多快。
  （类比：机器人手臂的轨迹规划结果。）
- **刀具** —— 机床上的切刀。模具加工常用平底刀、球刀。
- **刀具号（T01 / T02）** —— 给每把刀编的号，程序靠这个号告诉机床"现在换第几号刀"。
- **刀具表** —— 全机/全厂的刀具档案：编号、直径、刃数、长度。程序里用错刀号直接报废。
- **主轴转速 S** —— 刀转多快，单位转/分钟。太快烧刀，太慢崩刃。
- **进给 F** —— 刀往前推多快，单位毫米/分钟。
- **余量（Stock / Allowance）** —— 故意留着、先不切掉的那层料。粗加工留余量，精加工再切掉。
- **过切（Gouge）** —— 刀切到了不该切的地方，把零件切小了一块。**直接报废。**
- **欠切** —— 该切的地方没切干净。可以补一刀，比过切好收拾得多。
- **干涉 / 碰撞（Collision）** —— 刀杆、刀柄、夹具、工作台之间互相撞上了。
  **轻则撞刀报废，重则伤机床。**
- **行程（Travel）** —— 机床各轴能移动的最大范围。程序里写了超范围的坐标，轻则报警重则撞限位。
  （类比：内存越界。）
- **安全平面 / 安全高度** —— 一个约定好的"高处 Z 值"。刀不切东西的时候应该抬到它以上再横移。
  程序里快速下探到它以下，就是撞刀高危动作。
- **装夹 / 夹具（Fixture）** —— 把工件固定在机床上的东西。装夹方式决定刀能不能伸进去、从哪边下刀。
  **这是纯经验活，AI 不该拍板。**
- **刀补** —— 刀具的"尺寸修正"：
  - 刀长补偿（G43）：补偿每把刀实际长度不同。
  - 半径补偿（G41 / G42）：让机床按刀具半径偏移一个量走，**用了必须用 G40 取消**。
- **空运行（Dry run）** —— 让机床按程序走一遍但不真正切料（或抬高 Z 悬空走）。上机前的保命检查。
- **刀路仿真** —— 在软件里模拟切削过程，看会不会过切/撞刀。比空运行更早、更安全。

## 三、输出相关

- **后处理（Post-processing）** —— 把 NX 内部的刀路数据，翻译成某台机床能读懂的指令。
  （类比：把中间表示 IR 编译成目标机器的机器码。**不同机床 = 不同目标架构，必须各配一个后端。**）
- **G 代码 / NC 程序** —— 机床真正执行的指令文本，长这样：`G01 X80. Y0. F1500`
  （直线走刀到 X80 Y0，进给 1500）。（类比：汇编 / 机器码。**这是唯一能拿来做静态检查的东西。**）
- **后处理器** —— 做上面那个翻译的程序。NX 里由 Post Builder 生成，本质是几个文本文件。
- **TCL** —— 后处理器的脚本语言，一种很老但简单的脚本语言。改后处理就是在改 TCL。
  （类比：webpack 的配置文件，只不过写法像 shell。）
- **MOM 事件** —— NX 内部发出的"发生了某件事"的通知（比如"要换刀了"），
  TCL 后处理器订阅这些事件并输出对应代码。（类比：事件驱动的 callback / hook。）
- **程序单** —— 给车间操作工的"说明书"：用什么料、装夹怎么装、用哪几把刀、先做哪步。
- **工艺卡 / 刀具清单** —— 同上，把工艺和刀具列成表。
  **这些 99% 是纯文本工作，是 AI 最容易出成果的地方。**

## 四、编程接口（你要开发的部分）

- **NX Open** —— NX 提供的编程接口（API），支持 C#、C++、Java、Python、VB.NET。
  用它可以用代码干界面上能干的所有事。
  （类比：操作系统的 syscall 集合。**注意：是 syscall，不是标准库。**）
- **Journal（录制）** —— NX 的"宏录制"：点开始录制 → 手动操作一遍 → 停止，NX 自动生成代码。
  - **重点：录下来的不是元操作，而是一次完整的操作序列（编排）。**
    录出来的代码参数是写死的，要变成可复用的还得加工。
  - （类比：Playwright 的 codegen / DevTools 的 Recorder。）
- **Developer 选项卡** —— NX 界面里平时藏起来的开发用标签页，Journal 的播放按钮在里面。
- **Journal Language** —— 录制输出用什么语言。默认 VB，可改成 Python
  （`文件 > 首选项 > 用户界面`）。
- **批处理（Batch）** —— 不打开 NX 界面，在命令行里跑脚本。
  （类比：headless 模式 / CI 里跑无头浏览器。**要全自动必须走这条**，因为开着界面跑会卡住界面。）
- **run_journal.exe** —— NX 自带的命令行工具，用来在命令行跑一段 journal。
  路径 `%UGII_BASE_DIR%\NXBIN\run_journal.exe`。
- **UGOPEN / Programming Interfaces** —— NX 安装时的可选组件。
  **不装它，run_journal.exe 根本不存在。**
- **许可（License）** —— NX 的授权。
  - 好消息：**跑 journal（Python / VB.NET）不需要开发许可。**
  - 坏消息：**批处理模式需要许可里包含 batch 支持**，有些许可不含。

## 五、模具行业词

- **电极** —— 电火花加工用的"反向印章"。模具上有些死角铣刀伸不进去，就用铜电极通电烧出形状。
  一套模具常常要几十个电极，每个都要单独建模 + 编程 + 出图，所以是重复劳动的重灾区。
- **电火花（EDM）** —— 用放电腐蚀金属的加工方式。电极就是它的"刀"。
- **分型面** —— 模具分成上下两半时两者的接触面。它的形状决定脱模顺不顺。
  **这个"顺不顺"只能靠老师傅的眼睛判，AI 判不了。**

## 六、我们这套系统自造的词（不是 NX 官方词）

- **桥接（bridge）** —— 跑在 NX 里的那个小程序，负责"接指令、干活、回结果"。
  （类比：daemon / agent 进程。）
- **队列（queue）** —— 一个文件夹。Agent 往里丢请求文件，桥接把结果写回来。
  （类比：消息队列的最土版本。好处：跨机器共享盘也能用，企业网不用开端口。）
- **MCP** —— Model Context Protocol，让 Agent 能调用外部工具的标准协议。
  **它只解决"怎么调用"，不解决"调用什么"和"做对没有"。**
- **原语（Primitive）** —— 软件提供的最小操作单位（NX Open 里的一个函数）。
- **编排（Orchestration）** —— 把一串原语按正确顺序和上下文拼成"干成一件事"。
- **能力封装（Capability）** —— 给一次编排起名、定参数、加前置检查和后置校验，
  让它能安全地反复调用。
  （类比：从 syscall 到标准库函数。**NX 有 syscall，缺的就是这一层标准库。**）
- **判据（Criterion）** —— 判断"做对了没有"的客观标准。**没有判据就没有自治。**
